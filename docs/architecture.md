## Routes and lifecycle

- `#home` (also the fallback for unknown routes): house exterior, with To-dos below it.
- `#chores`: My tasks; `/personal`, `/assigned`, `/unassigned`, `/household`, `/week`, `/leaderboard` preserve view selection.
- `#miscellaneous`, `#events`, `#bulletin`, `#utilities`: current feature routes. Visible labels are Expenses and To-dos; old identifiers remain intentional.
- `#games`, `#games/geography`, `#games/geography/review`, `#games/scores`: hub, play, labeled globe and scores.
- Legacy `#home/personal` and `#home/assigned` redirect to To-dos. Notification query parameters focus the relevant record.

The six household scenes share an upward Games entrance. `sky-portal.ts` owns gesture eligibility/cancellation, and the house renderer owns the cloud ascent. Returning from a feature requires a fresh gesture before taking off. The return scroll waits for actual movement before applying its idle timer, so a delayed first rendered frame cannot dock the house again. The floating home icon retains scene/feature context in session storage; a neighboring telescope icon returns to the observatory. Direct feature URLs avoid house initialization. Feature modules initialize once and refresh on demand; route versions prevent late requests from affecting another route. Active sections refresh every 45 seconds and on visibility return when no dialog is open. Background task badges use a summary RPC. House/character renderers suspend when hidden, offscreen or behind dialogs and honor reduced motion.

The build creates content-hashed JavaScript, styles and public config, with module preloads for the requested section and navigation intent. Keep dynamic imports intact: household pages must not eagerly download atlas data or Three.js. `release-assets.json` records immutable JavaScript/CSS and their checksums. Both publishing paths retain these files from the preceding deployment for 30 days, so an already-open tab can finish loading its original modules. The first retained release also recovers files from available recent Pages artifacts. Retention never replaces current HTML, snapshots or the service worker. Module-load errors offer an explicit Reload action to refresh the page and its module graph; there is no automatic reload that could erase a draft. `public/sw.js` handles push only; it does not cache application pages or intercept payments.

## Data contracts

Supabase tables live in `ledger_private`, with RLS and direct anonymous table access revoked. The browser calls scoped `utilities_*` RPCs. Selected-name identity is public attribution, not authentication. Mutations validate expected versions, use request IDs for retries and retain revision/event records. Calculations are authoritative on the server; pure TypeScript helpers provide matching previews.

The local PGlite adapter loads migrations into a disposable or private local database. Schema changes require a new ordered SQL migration, local adapter support, setup detection, release capability checks and appropriate exports. Existing migrations, including one-time historical corrections, are necessary to reproduce/upgrade installations. Do not prune them as completed bookkeeping.

Six household fallback snapshots live in `data/`. Each source fails independently, labels saved data and disables its unavailable writes. Game progress is per person/device; competitive scores have a separate pending outbox and database RPCs. See [Atlas](geography-data.md).

## Validation and boundaries

Use `npm run check`, targeted domain tests and `npm run build` before browser checks. `tests/browser/` runs against the local isolated server; it must not create records on Supabase. Browser specs test saved records, retries, route transitions, mobile gestures and loading boundaries. Full release commands are in [README](../README.md); the deployment script also verifies live schema capabilities and refreshes snapshots.

Only sanitized data and approved derivatives enter `dist/`. Keep private PDF/import originals and artwork source packs outside it. GitHub Pages is the deployment target; this checkout is not a Sites-hosted project.

## Observatory and daily trivia

`src/games-client.ts` now owns the Games shell. The monumental observatory reuses the house cast and geometry helpers. Eight compact playing cards flank the building, using the same faceted model artwork, warm lighting and materials as the household scenes. The observatory stays visually dominant, with no decorative corner heading. A card brightens and lifts slightly once the telescope reaches its heading; the other cards stay quieter. Hover, focus, arrow controls and dragging select a card. Drag left to advance and right to go back, matching the house; Right/Next advances and Left/Previous goes back. The telescope aims at its actual screen position, by solving its projected heading at a fixed safe elevation; the raised barrel clears the widened dome slit. Card anchors remain stable during their focus animation, and drag updates apply immediately in either direction. Clicking a card opens its game immediately. The renderer uses one animation-frame clock for drawing, resizing and resuming, with bounded elapsed time and shortest-path headings. It pauses while hidden or behind a dialog, respects reduced motion, and cancels interrupted pointer drags. Navigating away also closes game-owned dialogs so browser Back cannot leave a modal over the hub. Failed initial loads can retry on the next hub visit. Context loss shows the SVG building and rendered sky poster until graphics recover; the 3D backdrop is shown only after a successful frame. Scheduled refreshes retain active trivia boards and input focus; score screens still refresh. Geography is isolated in `src/geography-client.ts`; its assets load only when opening Geography or its scores. `#games` is the observatory; existing geography routes remain compatible. New game routes are `#games/{odd-one-out,passport-puzzle,clue-cascade,before-or-after,how-much-ish,sudoku,crossword}`, with `/scores` for standings.

Trivia uses typed questions and pure practice scoring in `src/trivia-model.ts`. Each practice bank is dynamically imported independently. Daily content is private database data, with unrevealed answers omitted from RPC responses. Migration 031 adds versioned packs, attempts, and narrow start/action/scores/export RPCs. Migration 032 adds content v2 and preserves v1 packs and in-progress attempts. If someone started an older pack on rollout day, all roommates get that same version for that game until the next day. Migration 033 introduces Common Ground and sourced size comparisons as content v3; 034 retains the original typed-capital scoring, 035 adds capital-city dot scores, 036 adds server-validated daily border trails, 037 adds the larger city catalog, 038 refines its selection and creates a new `urban` scoring category while preserving old pool totals, and 039 adds size comparisons v4. Migration 040 adds immutable online catalog imports and variable-length daily rotations; 041 seeds the first Wikidata catalog. Migrations 042–044 add per-person archives, ten starter packs, original Sudoku/crossword dailies, and photographic size silhouettes. Migration 045 replaces new Passport boards with reviewed cultural, sporting and historical clues while retaining pinned attempts. Migration 046 adds authoritative grid clocks and global Border Trail mechanics; 047 adds the curated size catalog. Migration 048 makes Border Trail release metadata readable without private-table access. Migration 049 gives routes equal scoring and connected feedback from either endpoint. Migration 050 adds the fresh size catalog and separate category shelves. Migration 051 adds paused grid clocks. The local adapter and release checks require migrations through 051. Selected names remain attribution, following the existing household trust model.

A day is midnight-to-midnight in America/New_York. One attempt per player/game/day resumes across devices. Answer writes serialize and reject conflicting retries; clue requests use an explicit target level, making retries idempotent. Daily scoring is server-authoritative. Expired attempts retain earned points, with unanswered questions worth zero. Monday–Sunday standings sum the five best days per game. Equal totals share rank except Sudoku/Crossword, where lower total completion time breaks ties. Grid clocks pause when switching games, opening scores, hiding the tab or leaving the page, and resume with their accumulated time. Practice stores paused checkpoints. Daily clocks use server-timed intervals with revision checks and an owner per visit, so stale pauses cannot stop a newer tab. A heartbeat renews a 30-second lease, bounding time if a tab disappears before its pause arrives. Retries cannot reset accumulated time or overwrite a finished result. Existing elapsed time is preserved when an unfinished legacy attempt first adopts the new clock. Older untimed results remain intact and sort after timed results with equal points. Geography scoring is independent, with separate name, find, mixed-city and historical capital-only categories; daily Border Trail has its own standings. Ranked trivia requires a connection. Practice drafts and progress sync through versioned archive RPCs, with local caching; guests play on-device. Sudoku pencil notes remain on-device. A completed or expired attempt is immutable.

Content v2 has fourteen daily packs per game and separate practice banks (twenty questions, or four timelines). These legacy packs remain readable for historical attempts. Current practice uses fixed calendar entries. `scripts/trivia/curated-v2.py` contains edited category puzzles, word associations, landmarks and explicitly dated milestones. `build-content.py` deterministically packs them, generates country outlines from the existing atlas, and authors migration 032. Daily answers, aliases, explanations, sources and timeline dates remain private until submission. Future editorial revisions need a new content version and additive migration; do not rewrite released packs.

The boards have distinct interactions: Odd One Out uses category tiles; Passport Puzzle uses country outlines with progressive field notes; Common Ground sorts sixteen words into four groups; Before or After uses illustrated cards with pointer/touch sorting, tap-to-place, and keyboard pickup/move/drop controls; How Much-ish moves silhouettes around a shared zoomable grid and resizes the target from a separate handle; Sudoku supports notes and undo; Crossword has crossing clues, direction switching, letter keys and automatic advancement to the next unfinished entry. `scripts/render-game-card-art.mjs` renders `src/game-planets.ts` with the shared `house/scene-geometry.ts` helpers into eight small transparent WebPs. `src/game-card-assets.json` records content-hashed filenames checked by the build and privacy checker. These local images also work without WebGL; they do not add more rendering contexts. Entry starts or resumes the board directly; guests start Practice. Daily/Practice switching is available on the board, and loading failures offer Retry. Standings show four score-scaled bars with Bitmoji and crowns; detailed ranks are collapsed beneath.

Common Ground retains the `clue-cascade` route and database game key for compatibility. Four mistakes end the board; each solved group earns 250 points. Partial progress lives in `trivia_attempts.progress`, including solved groups and previous guesses. Group submissions lock the attempt; repeating the same four words in any order costs no extra mistake. A three-word overlap receives “One word away.” Unsolved categories remain private until the board ends. The old answer RPC is private and continues to serve pinned v1/v2 attempts. `scripts/trivia/groups-v3.py` authors twenty-six original boards: fourteen daily and twelve separate practice boards. `build-v3.py` writes content v3 and migration 033. Run it after the v2 builder, which also writes legacy practice banks. These are finite curated banks, not live generated trivia. Before or After supplements its practice bank and Passport replaces its practice bank; both replace their daily rotations with the selected online catalog described in [game-sync.md](game-sync.md). Sync runs outside the browser; game play uses private, versioned database packs.

Early design references included [Worldle](https://worldle.teuteuf.fr/) for geographic inference from shape, [Chronophoto](https://www.chronophoto.app/) for reasoning about time, [Size It Up](https://www.sizeitup.co/) for direct manipulation of relative scale, and four-group word sorting for Common Ground. Application code and puzzle pairings are original. The current How Much-ish catalog uses geometry and measurements from Magnitudle’s public archive, with provenance and credits described below.



The observatory backdrop is a three-layer celestial landscape in `src/observatory-cosmos.ts`, rendered in the same Three.js scene and lighting as the building. It keeps a small distant cratered moon and ringed planet at the edges, with sparse faceted clouds and asteroids and two small crystal constellations. The decorative planets are about one fifth of their original size, so the observatory and game cards remain the focal point. Stars are instanced; stationary geometry is batched. Pointer parallax changes each depth layer by a different amount, pauses when the hub is hidden, and is disabled with reduced motion. Scenery is positioned separately for narrow screens. There are no backdrop hit targets or extra UI controls.

`node scripts/render-observatory-sky.mjs` renders wide and phone WebP posters from that same geometry for loading and WebGL failure. `src/observatory-sky-assets.json` records their content-hashed filenames; the build only permits that explicit asset pattern. The posters replace the earlier flat SVG artwork. They are hidden once the live 3D scene is ready and return after context loss.

Border Trail temporarily uses the existing Paper renderer without overwriting the user’s preferred globe style, showing only discovered country polygons with stable pastel fills and a gold destination; its pure rules are in `src/geography-route.ts`. Country and city games retain the complete globe. Cities use distinct location IDs, even within one country, and render/grade each city point independently. Practice progress from capital-only city rounds is extended; older ranked rounds are archived on-device and replaced with a fresh mixed-city round so their scores do not enter the new leaderboard.

`src/timeline-sort.ts` handles Before or After sorting without the old per-card arrow buttons. A lifted preview follows pointer or touch input while the faded original marks its destination; short screens scroll at the edge during a drag. Space/Enter picks up and places a card, arrow keys/Home/End change its position, and Escape cancels. Two taps also move a card without dragging. Reorders update the existing saved draft. After submission, `src/timeline-review.ts` shows the unchanged submitted order beside the correct chronological order, with dates, right-place indicators and explicit position corrections. It explains the existing pairwise score, retains frozen daily answers, and reads dates from old v1 explanations when no structured reveal exists. Both columns remain adjacent on phones; revealed results cannot be reordered. Interrupted pointer gestures restore their starting order; reduced motion disables the tile slide animations.

All seven trivia boards follow the shared household light/dark preference through `data-theme`, including System and Time of day. Dark styles in `public/games.css` keep each board's palette and cover selection, dragging, solved groups, answer reviews, and scores. The small game theme control reuses the house control's icons, labels, cycling, and stored preference through `themeToggleMarkup` in `src/settings.ts`; changing it updates colors without rerendering the puzzle or clearing its draft.

`src/game-library.ts` provides the ten starter entries plus each past New York day available for that game. Completed dailies retain their result; missed or partially played dailies can be continued unranked without changing the original ranking. The database first uses the household's pinned day/version/slot, then reconstructs missed days from release availability. Migration 042 tracks future imported pack availability automatically. Practice save RPCs use revision checks and serialize concurrent writes; the browser retains dirty drafts offline and retries on reopening. A conflicting local copy is kept under an `:unsynced` key rather than overwriting another device. Selected entries and modes are remembered separately for each person and game. Earlier local trivia (except How Much-ish, whose history was reset) and Border Trail practice is retained as an Earlier calendar tile on that device. Geography currently archives Border Trail; open-ended country and city practice still use their existing saved rounds.

`src/daily-run.ts` reads completion status without starting attempts and advances through unfinished games. The hub's calendar shortcut begins this sequence; result screens and the floating shortcut continue it. The floating navigation orders Observatory before Home. Shared person selection lives in Settings, including a gear within each trivia game and the hub.



Border Trail uses the same Paper globe and interaction controls. Its v2 rules accept countries in any order, retain each guess once, and solve when guessed countries connect both prefilled endpoints. Both connected endpoint branches remain visible on the globe. Weighted shortest paths grade progress; optimal intermediate-country count determines the guess budget. In-order minimum routes in either direction score 1,000, out-of-order minimum routes 975, and each excess guess costs 100. `build-world-routes.py` appends 60 interleaved routes (2–16 intermediate countries), retaining original puzzle IDs. New starters use IDs 48–57; daily cohorts pin a puzzle across players. Archive reconstruction uses release availability and the actual historical puzzle ID. Channel Tunnel, Denmark–Sweden and Malaysia–Singapore connections are included; detached Azerbaijan/Angola/Palestine shortcuts are excluded. This retains our atlas rather than reproducing Travle’s separate territory model.

`centerArchive` scrolls only the horizontal archive strip after mounting, centering the selected tile without moving the game page. Both trivia and Border Trail call it after loading.


Current How Much-ish content is v11: 300 detailed profiles (110 Classic, 55 Pop culture, 135 Geography), 450 category practice comparisons and 180 mixed daily five-round boards. `src/size-catalog/{category}.json` loads only when that category is needed; the combined catalog is retained for generation and validation only. `scripts/size-art/catalog-manifest.json` pins public Magnitudle archive responses, path hashes, artwork credit records, sources and measurement definitions. `import-catalog.mjs` preserves every contour and hole, simplifies redundant tracing points, measures visible bounds in Chromium, and generates the catalog and question banks. It excludes artwork explicitly marked Owned. AI-generated profiles retain the source’s “no ownership claimed” statement; this is recorded separately from open licenses. Natural Earth, geoBoundaries and licensed artwork retain their attribution and license links. Geography compares the stated projected extent, not land area; specimen and fictional-version qualifiers appear beside the names. Measurement notes disclose full-outline calibration from a key measurement. Builds and gameplay use the committed snapshot, with no third-party requests.

`src/size-game.ts` owns the board. Drag either silhouette to move it; drag the target’s corner handle or use its arrow keys to resize. Small/Large buttons provide additional touch controls. Drag the background to pan; wheel, pinch, +/- or zoom buttons move the single camera. Fit restores both visible silhouettes, including the correct size after checking. All silhouettes share pixels per metre. Camera changes and translations never change the ratio or score. The handle stays reachable at extreme sizes, viewport changes fit the scene, and pointer cancellation restores the starting gesture. Draft ratios sync through the archive; camera and positions are local per person/board/round.

Check reveals a copper actual-size silhouette over the translucent estimate, plain directional error, comparable measurements, and the existing score out of 200. Fresh submissions animate the actual silhouette and count the score up, then give a brief score pulse and best-effort touch haptic. Fine-pointer devices play a short synthesized chime, unlocked by the submit gesture; the sound button remembers mute locally. Reloading or reviewing a result does not replay the feedback. Reduced motion skips the count and visual pulse. The full five-round game remains out of 1,000.
